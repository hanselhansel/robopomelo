# Changelog

RoboPomelo product and package release notes. Specification versions are recorded separately.

## [1.0.0] - 2026-09-05

### Added

- Plan a warehouse AMR deployment through five connected steps in a local browser, terminal wizard, or CLI. Start blank or explore the clearly labeled fictional inbound-pallet example.
- Record needs, material flows, requirements, KPIs, acceptance plans, and engineering questions with explicit missing, unknown, unverified, and not-applicable states. Check readiness and trace related records using the same deterministic rules in every interface.
- Save readable YAML with comments and extension data, exact quantities, stable record identities, and revision history. Preserve unfinished input, inspect cumulative proposals, and resolve conflicting or external changes before applying them.
- Grant and revoke project-specific permissions. Record attributed approvals, acknowledgments, waivers, and revocations separately from authoring, and invalidate approvals when their reviewed planning context changes.
- Add explicitly selected evidence with byte-integrity checks. Export exact source, review and acceptance documents, an engineering handoff, validation findings, and a member manifest as files or a deterministic ZIP.
- Restore authored history while preserving current review records. Inspect interrupted operations, recover verified backups into an empty folder, and require fresh trust for the restored project.
- Use six bounded Agent Skills through the ordinary-file and CLI path. Core planning needs no model API, project upload, robot connection, or remote UI assets.
- Install a self-contained package with verified runtime selection, compatible stable updates, offline mode, version pins, and persistent rollback holds. Read guides for installation, terminal use, permissions, recovery, contributions, and host compatibility.

### Changed

- Keep large planning and review screens responsive by deferring unopened editors and paging long document sections, while retaining complete print output.

### Fixed

- Include limited filesystem error identifiers in local failure responses without exposing paths, project content or credentials.

- Verify shutdown across launcher and runtime processes before removing temporary test projects, and allow pending durable operations to complete before asserting their UI results in hosted verification.

- Keep selected evidence bound to its original bytes even when file timestamps are delayed. Wait for failed runtime processes to close and retry a lock entry released during acquisition.
- Retain newer input when a reviewed proposal commits, distinguish committed retries from pending changes, and preserve drafts through lost responses, external edits, and navigation.
- Preserve explicitly named examples, current engineering-question versions, actionable errors, and exact runtime identities and saved offline preferences.
- Keep modal keyboard navigation contained, retain parked forms, and preserve ordered headings and readable A4/Letter review layouts.
- Recheck project selection after request-body parsing, reject malformed or oversized requests, and keep source-checkout execution outside installed-runtime update operations.
- Flush recovery, backup, restore, and export directory entries before publishing completion, and reject conflicting update-policy changes rather than silently discarding them.

### Verification note

Manual screen-reader testing is deferred for v1 with maintainer approval and remains unverified. Automated accessibility, keyboard, browser, package and release checks remain required. See [local acceptance evidence](docs/verification/v1-local-acceptance.md).
