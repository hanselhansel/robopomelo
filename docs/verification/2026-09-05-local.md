Recorded 2026-09-05. These checks verify local implementation. They do not establish publication, native CI success, customer validation or physical deployment readiness.

## Installed package

The generated 1.0.0-rc.1 tarball passed exact runtime-manifest inventory, npm packed inventory, installation into a separate temporary directory, declared-bin execution through `npm exec`, offline version reporting, fictional example creation, validation, seven-file export, protected browser bootstrap and document review HTTP readback. `scripts/verify-package.mjs` repeats these checks against any supplied distribution and can install the original signed tarball with `--tarball`.

Record hardware/runtime and competing workload before comparing another machine. A faster input response does not imply faster durable storage.

## First publication mechanism

The npm `trust` command requires an existing package and account-level two-factor authentication. The first real candidate can be built and signed in the authorized GitHub release workflow, then published from the authenticated maintainer terminal using npm's supported `--provenance-file` option. After it exists, the exact GitHub trusted publisher is configured for subsequent releases. No placeholder version or transferred npm credential is needed.

The pinned official `libnpmpublish` 12.0.0 generator produces npm's normal SLSA statement and Sigstore bundle. Local bootstrap verification uses RoboPomelo's production publisher identity, signature and archive checks before the original tarball is installed or published. `scripts/verify-release.mjs` then independently checks the actual registry artifact. Stable `latest` promotion requires fresh passing proof and exact integrity readback.
